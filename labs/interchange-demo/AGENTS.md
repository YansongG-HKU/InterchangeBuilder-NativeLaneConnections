# 仓库执行规则

## 优先级与范围
- 本仓库是非主业的爱好探索，默认小批次、可逆、低成本；不建立自动高频推进任务，不挤占主业资源。
- 先读 README、docs/DEVELOPMENT.md、docs/DOCUMENTATION_INDEX.md、docs/COMPATIBILITY.md 和相关实验记录，再修改。
- 仓库文件是事实；Issue/讨论是提案，未实施和未验证不能写成已完成。

## 每次开发与提交的强制门禁
1. 明确问题、范围、接受条件、目标游戏/Mod 版本及回滚方法。
2. 全面检查全部受版本控制的文档，填写变更影响记录；更新所有受影响的 README、规则、来源、兼容矩阵、测试、计划、变更记录与示例。
3. 文档、配置、模型、测试和实现必须对同一状态达成一致；不得遗留矛盾或失效链接。
4. 在提交中包含所需同步文档；每次提交均说明验证范围及未运行项。不可把“未运行”写成通过。
5. 非初始化变更使用主题分支及 Draft PR；审查后才按获批范围合并、发布，不强推共享分支。
6. 提交前核对 diff、文件清单、敏感数据、外部素材授权、版本和依赖；不提交存档隐私、日志令牌、未许可游戏或 Mod 文件。
7. 游戏内验证必须真实执行并保留版本、步骤、日志/截图和保存重载证据；视觉连上不等于网络连通。

## 兼容规则
- 不将 CS1 教程/API、Road Builder 网络定义、装饰网格和可通车节点混为一谈。
- 无碰撞/Anarchy 只改变部分编辑限制，不能证明路径、车道方向、净空和升级行为正确。
- Mod 版本、依赖或配置变更后，旧通过记录转为待复验；保护原始实验及旧证据。
- 已知失败也应如实留档；未知数据不补造。未经验证不采用统一的节点间距、坡度、面数等“硬规则”。

## 环境与授权
仅使用已获授权的云端环境。禁止自行购买资源、操作用户电脑、创建凭据、改变安全设置或上传第三方内容。公开初始化仅授权本仓库准备资料，不授权游戏正式发布。

## 设计阶段新增约束
实现前先读四份第一阶段设计文档。中英用户体验从首阶段同交付；full access、free flow与形态模板分开；新流向/几何规则必须更新验收用例及来源。未支持的道路/车道显式拒绝，禁止静默替换。
