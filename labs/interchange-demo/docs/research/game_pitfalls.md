# 立交设计补充：CS2 游戏行为与验收陷阱 / Game-side pitfalls

研究日期：2026-10-25 UTC。性质：设计研究，不是实现、实测或兼容性认证。所有下列实验均 **NOT_RUN**。不修改现有仓库文件。证据等级：A=官方已发布说明；B=模组作者文档（非本项目复现）；C=社区个案；D=本项目建议/待验证推论。2023 功能日记只能作历史背景，不能替代当前构建测试。

## 一、此次新增的可靠证据

- **A，版本敏感的换道行为**：官方 1.5.9f1（2026-05-27）明确调整高速出口/路口前提前选择转向车道，并减少非必要 U-turn。[正式补丁](https://www.paradoxinteractive.com/games/cities-skylines-ii/news/patch-notes-morning-dew)。因此“某节点固定距离必修好所有出口”不是稳定游戏规则。
- **A，路上车辆少不等于需求已服务**：官方 1.6.0f1（2026-06-22）调整出行范围及无路可走的处理，不同出行类型可能搬离传送、放弃工作、留家重试；1.6.2f1（2026-09-15）修复停车相关车辆消失后引发额外取车行程的问题，并更新 UI 框架、提示部分模组受影响。[官方 Steam 公告](https://steamcommunity.com/app/949230/announcements/)。这是本次查到的最近已发布版本线索，不代表检查了用户实际安装版。
- **A，历史背景**：2023 Traffic AI 日记把路径选择描述为时间、舒适、金钱、行为等共同影响；流畅度与交通量是不同指标。[Traffic AI](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/traffic-ai)。不要把几何最短/视觉最顺直接当作实际首选路线。
- **B，编辑后的断路风险**：Traffic README 记载，新增相交道路可能需重建自定义连接；变更道路构成、方向等会移除连接；Road Builder 操作可能重置连接及优先级；缺失 Traffic 后读档再更新网络会恢复默认。[作者 README](https://github.com/krzychu124/Traffic)。这是作者当前页面说明，不是已确认用户版本必现。
- **B，缺失依赖的降级**：Road Builder 作者要求分享含自定义道路的存档声明依赖；缺失模组时自定义道路可能呈默认灰网络。[Road Builder](https://github.com/JadHajjar/RoadBuilder-CSII)。能打开存档不等于道路功能完整。
- **B，无碰撞不等于通过验收**：Anarchy 作者列出可抑制 tight curve、short distance、steep slope 等错误，并允许违反其他网络净空。[Anarchy](https://github.com/yenyang/Anarchy)。项目应保留独立几何/净空/拓扑检查，不把模组消除红色报错当作安全证明。
- **A，历史背景**：官方 Road Tools 描述交通灯、斑马线、停牌、转向控制和道路维护；路况、积雪、事故会影响交通。[Road Tools](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/road-tools)。验收须记录这些变量，不将全部堵塞归因于匝道形状。
- **C，实际用户痛点**：CS2 社区帖作者报告将出口前节点后移后换道改善；评论提到 6→2+4 仍只用一条出口车道。[个案原帖](https://www.reddit.com/r/CitiesSkylines2/comments/1x27ho8/how_to_fix_traffic_at_intersection/)。可生成测试用例，不足以推出统一间距阈值、因果关系或所有存档规律。
- **B，待独立复现的服务车辆风险**：EmergencyPriority 作者宣称修复拥堵中应急车辆消失/不重新规划的问题。[作者仓库](https://github.com/AmicusDeus/EmergencyPriority)。未审核其实现、适用构建或复现，不能写成当前所有原版 CS2 的既定事实，更不应因此擅自新增依赖。

## 二、建议补入的需求（D，尚未实现）

|优先级|注意事项|可执行设计要求|
|---|---|---|
|P0|设计车道图 ≠ 游戏生成车道图|生成后回读每个端口的有向车道连接、转向许可与控制状态；验证每个要求的 OD 真正可达，且无意外 U-turn 或平面交叉。预览与结果不符应中止或明确报错。|
|P0|出口堵在下游，回灌到高速|验收边界至少含匝道末端与邻接路口。展示排队尾端及储车空间；不能只优化高速上的分叉点。|
|P0|6→4+2 不保证两条出口均匀使用|用不同出口目的地比例分别测试；标清一条车道可达哪些目的地。不可把强行均匀分配设为通用目标。|
|P0|路权控制必须显式|逐端口记录 traffic light/stop/yield/priority/turn restrictions；游戏或模组无法设置时显示不支持，而不是仅画一块标志。匝道末端灯控可合法存在，全互通不等于全无信号。|
|P0|左右行不能只翻转网格|重建车道方向、入口/出口侧、让行关系与路标朝向；用镜像 OD 对验证。不得只翻转纹理或混淆左右行与中英语言。|
|P0|道路编辑、升级和存读档后退化|在 Road Builder 单实例与全实例编辑、方向反转、Traffic 连接调整、存读档、缺失依赖等状态后重验。保留改变前快照；无法恢复不得宣称兼容。|
|P0|指标掩盖未服务需求|流畅度仅辅助，核心同时记录实际输入、完成、未完成、消失/清除（若可观测）、队长和旅行时间；数据不可获得须明确局限。|
|P1|服务与货运可达性|按消防/救护/警务/垃圾/道路维护/货运分别检查进出路径，含另一侧服务设施和返回路径。不能用普通小汽车成功代替全类别通过。|
|P1|节点数量与短段|间距作为可调实验变量，不填未经验证的硬下限；拒绝零长、重复、误吸附连接；同形状比较不同分段，检查换道与运行成本。|
|P1|真实建造代价|对比占地、桥梁/地面长度、土方影响、游戏报价与维护费用；费用用游戏当前值，不填永久常数。|
|P1|性能预算|同时测预览交互耗时、生成时间、实体/节点数量、保存大小变化、加载耗时、模拟推进速率和渲染帧时间；FPS 好不代表模拟速度正常。|

## 三、增补验收实验 / Acceptance experiments（均 NOT_RUN）

**公共协议**：冻结游戏 build、模组版本/设置/加载顺序、道路 prefab/config、左右行、地图与存档、车辆类别、天气/路况、下游控制、人口就业和观察窗口；从同一存档分支 A/B；同样预热期与模拟时间长度；改动一个因素。不能保证随机种子/需求完全相同，则做多次重复、报告波动并标为观察性测试，不称固定容量实验。

1. **G01 节点敏感性（P0）**：同一个曲线 6→4+2，分别改变出口上游分段位置，保持端点/车道/下游/需求一致。比较出口两车道使用、提前换道位置、完成量和主线队尾；不以“肉眼更顺”判定成功。
2. **G02 下游阻塞（P0）**：空闲出口、一个末端路口饱和、邻近两个出入口串联三组。报告最坏队尾是否越过分流点、是否阻断直行车道。跨出观察区队列按超界报告，不能截断为短队列。
3. **G03 逐车道 OD（P0）**：遍历定义好的必要方向对；固定允许车辆类别，分别验证生成、加载、升级后真实连接。路径不能通过立交边界外绕路充数。偏置 OD 与均衡 OD 各测一组。
4. **G04 控制与镜像（P0）**：相同几何/需求在左右行版本验证入口让行、末端信号、标线、禁止方向；控制手段缺失时明确失败/不支持。用同一字典作中英一致性检查。
5. **G05 模组生命周期（P0）**：原版基线、Road Builder、Traffic、Anarchy、组合分别建矩阵；编辑道路后保存→退出→读档→网络更新；备份副本测试缺失依赖。记录实际状态而不是“存档加载成功”。不在用户唯一存档上试验。
6. **G06 反伪改进（P0）**：A/B 除流畅度还比较输入需求、到达、未完成、队长和时间；若清车、路径失败、需求下降、观察期不同，不得判 B 更优。无法追踪 despawn 时写 UNKNOWN，而不是零。
7. **G07 服务接入（P1）**：高峰队列中分别触发/观察服务和货运行程；记录实际抵达与返回、等待、失败，不根据应急灯或连接线推断成功。若无法可靠触发则保留 NOT_RUN。
8. **G08 成本/规模（P1）**：相同功能的紧凑、宽松、集散道三个候选记录占地、游戏报价、维护与模拟成本；对多个实例重复布置观察增长，不预设线性或恒定 FPS。

## 四、不可写成承诺的结论

没有已验证的万能节点间距、保证均匀用道的车道数公式、永久游戏坡度/净空上限、对所有 Road Builder 道路的支持或全模组兼容。也不能承诺无堵塞、无消失、应急车辆必达。清车后截图、截图好看、无碰撞能放下、存档能加载、一个总流畅度百分比，均不足以通过立交验收。
