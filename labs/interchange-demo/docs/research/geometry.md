# 曲线立交、逐车道连接与互通覆盖设计研究

证据核查：2026-10-25 UTC。状态：**研究与提议，未实现、未通过游戏测试**。当前游戏及 Mod 精确版本尚未锁定。所有下文 REQ 条目是本项目建议，不冒称原版游戏规则。

## 1. 证据边界

- **游戏官方事实**：2023-06-19 官方 Road Tools 文章描述曲线、平行道路、连接不同道路宽度、道路高程与坡度提示，以及用增加车道的路段接单车道高速形成加减速车道的构建方式。文章不是当前版本节点距离、半径、坡度、净空数值规范。[官方 Road Tools](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/road-tools)
- **Mod 作者约束**：Traffic 的逐车道连接必须在路网改动后重新核验；作者明确列出道路构成/方向修改可能重置或留下断开的连接，Road Builder 修改实例也会重置连接与优先权。不能仅凭路面贴合宣称连通。[Traffic 作者 README](https://github.com/krzychu124/Traffic)
- **真实工程参考，不是游戏硬限制**：FHWA 提醒考虑完整通行方向、主路线连续、交织、加减速、出口排队和场地条件；其 lane balance 包含出口选择车道，因此不等同于任何情况下都满足“输入车道数=输出车道数”。该页面最后更新 2012-04-12，不作为现行法律/工程合规判断或游戏数值依据。[FHWA Promptlist](https://highways.dot.gov/field-offices/missouri/interchange-design-promptlist)
- **仿真数据模型参考，不是 CS2 API**：ASAM OpenDRIVE 将道路连接和逐车道连接区分；1.8.1 的 direct junction 展示分流、合流及共用选择车道，且专门约束同向衔接。我们借鉴语义分层，不承诺 OpenDRIVE 导入，也不套用它的特定节点限制。[ASAM 1.8.1，2024-11-21](https://simulation.pages.asam.net/opendrive-group/opendrive-antora-gen/ASAM_OpenDRIVE_Specification/v1.8.1/specification/12_junctions/12_06_direct_junctions.html)
- **社区痛点，不是规则**：2025-05-27 至 28 日的 CS2 Steam 讨论反映距离难估、曲线对齐和吸附定位不直观。可据此提出明确距离/节点标记及数值输入需求；不能把回帖的手工画法变成通用算法。[社区原帖](https://steamcommunity.com/app/949230/discussions/0/601905642111775395/)

## 2. 6→4+2 必须分成“数量、用途、连接”三层

**REQ-L01 单向口径**：UI 明确“单方向 6 车道”与“双向合计 6 车道”；每条车道保存道路实例、行驶方向、语义 ID、宽度、车辆类别和用途。不得用左右屏幕位置或短期数组索引代替稳定方向语义。

**REQ-L02 模式不可混淆**：第一阶段设计覆盖：

1. 独占分流：6→4+2，例如按行驶方向从内到外标号，L1–L4→主线 M1–M4，L5–L6→匝道 R1–R2。
2. 共用选择车道：某条源车道同时可达主线与匝道；计数不能沿用独占分流规则。原型示例可以是 5→4+2，其中一条为 option lane。
3. 辅助/减速车道：新增后驶出，与把原有直行车道强制变成出口专用车道不同。
4. 汇入：4+2→6 的车道延续模式，与 4+2→4 的合流减道模式不同；后者必须标明让行/汇入/减道区段，不能伪装为两个入口各自独占同一出口车道。

这些是设计模式，不保证所有 Road Builder 横断面或游戏节点均可实现。能力不足应返回“不支持此道路组合”，而不是悄悄替换车道数。

**REQ-L03 验收看有向车道图**：检查每个被要求的源车道是否具有有效去向、目标车道是否方向/车辆类别正确、是否出现意外孤立、重复冲突、逆行、横穿其他连续车道或连续多次换道。独占分流不能仅靠 6=4+2 判 PASS。

**REQ-L04 RHT/LHT**：右侧/左侧通行均在需求中；“内侧/外侧”“出口侧”相对于行驶方向定义。镜像不仅翻几何，也重建车道序号、进出方向、匝道转向、优先权和标识。默认外侧出口，允许显式选择内侧出口并提示。

**REQ-L05 编辑后重验**：替换道路、Road Builder 修改横断面、删/合并节点后，对受影响车道连接重新读回核验。保存变更前后映射；不允许以旧缓存连接宣布成功。无法安全恢复时暂停确认，不擅自重置其他道路连接。

## 3. 两条曲线不是旋转后的正交模板

**REQ-G01 输入域**：用户选择道路 A/B 的有效路段及方向；支持曲线×曲线、曲线×直线、非对称路宽、S 弯、不同高程。既有主线默认锁定，确需改线必须预览并显式确认。

**REQ-G02 局部坐标**：用沿中心线的弧长 s 定位出入口锚点，不用全局 X/Y 距离替代沿路距离。取各锚点的局部切向和法向构建道路局部坐标；用两条道路切向计算有符号交角，而非假设东南西北。曲线方向反转时语义必须保持正确。

建议计算表达（自拟算法方向，不是游戏 API）：给定平面中心线 p(s)，单位切向 T=p'(s)/|p'(s)|，平面法向 N=(-T_y,T_x)，偏移轮廓 q(s)=p(s)+d(s)N(s)。交角可用 atan2(cross(Ta,Tb),dot(Ta,Tb))。坡度按高度相对水平弧长的变化计算；必须区分水平弧长与 3D 路径长度。曲率以数值稳定方式计算，零长/零导数要拒绝而非除零。

**REQ-G03 多解与退化**：两曲线可能多次相交、不相交但接近、平行、近切、局部重叠。列出候选交会区并让用户选择，不能默认第一个交点；近切情况下不能用病态交点无限拉长匝道。需要数值公差、去重及空间索引，公差记入测试配置。

**REQ-G04 几何与拓扑分离**：平面相交不代表应生成同层节点。先明确跨越/相交及层级，再建立连接；桥上桥下不能因俯视交点误连。匝道端点必须实际附着到目标网络，不只是视觉重合。

**REQ-G05 连续性**：端点位置与切向至少满足项目设定容差下的 C0/G1；曲率突变、折角、坡度突变可诊断。G2/缓和曲线仅在求解与游戏表示支持时作为更高质量目标，不能把“看起来顺”或两个 Bézier 端点相同称为曲率连续。匝道沿主线曲线先形成合理渐变/加减速区，再转入连接段；不得把弯曲道路强行拉直套模板。

**REQ-G06 全宽度检查**：检查道路/路肩/隔离带的扫掠轮廓，而不只中心线。紧曲线偏移可能自交；变宽分流区可能重叠；两车道曲线必须检查实际内侧空间。发现自交、反折、宽度负值或退化段应拒绝方案并定位问题。

**REQ-G07 三维与场地**：高程、纵坡及变坡、桥底到下方通行包络的净空、桥墩、地形、水面、隧道口和既有建筑分别检查。中心线高差≠桥下净空。坡度/半径/净空界限来自注明版本的游戏实测或用户设计配置；暂未证实的值显示 UNKNOWN，不能给绿勾。

**REQ-G08 无解可解释**：空间/坡度/路型能力不满足时，说明哪一约束失败，给出占地更大、换结构、改目标速度/设计参数等候选；不得静默改成正交道路、减少需求方向或打开无碰撞。

## 4. 全互通/部分互通以 movement matrix 定义

**REQ-M01 三个独立选项**：①通行覆盖：全/自定义部分；②交通控制：自由流/允许平交、信号或环岛；③结构模板。形状对称不等于完整；“部分苜蓿叶形”不自动等于缺少通行方向。

**REQ-M02 有向 OD 表**：每个进入方向→离开方向分为 Required / Optional / Forbidden，掉头单独开启。四臂道路在不含掉头时可能有 12 个有向动作（含 4 个直行和 8 个跨道路转向）；仅当定义清楚“只计两道路间转向”时才说 8 个。三臂/单向/封闭方向必须按实际入口出口集合生成，不能固定套 8。

**REQ-M03 验收**：对 Required 在逐车道有向图中找到合法路径；对 Forbidden 验证没有被生成的意外通路；已有直行必须保持。记录路径是否在立交内完成、是否需要绕邻近路口、是否存在信号/让行/掉头。外部绕行不能无提示地充作直接互通。

**REQ-M04 冲突与交织**：分别标记分流、合流、同层交叉、短距连续换道和入口后立即出口的交织段。报告可用沿路长度、需跨越车道数及受影响动作。风险提示不能伪称真实交通容量或拥堵预测；静态拓扑正确后还需游戏车辆寻路/排队回堵测试。

**REQ-M05 流量与路线优先**：支持指定主路线及主要转向需求；可选需求权重用于方案排序。没有流量数据时不声称容量最优。预留集散道/编织匝道、主线保持、出口排队空间与后续扩建需求。

## 5. 预览及安全应用需求

- 俯视与侧视联动；逐车道箭头、锚点弧长、局部切向、交角、最大坡度位置、净空最小位置、OD 覆盖矩阵和冲突区均可选中定位。
- 颜色之外提供图标、编号和中英双语错误文字；明确区分 ERROR / WARNING / UNKNOWN / VERIFIED。
- 实时预览有数值输入与拖拽两种方式；对比占地、道路长度、桥隧长度、最大坡度和缺失动作，但未验证成本/容量不标为准确值。
- 应用之前显示新增/拆除/替换对象与依赖；取消不修改地图，应用事务失败不留下半条路；撤销策略须验证游戏能力，不能预先保证万能撤销。
- Network Tools 作者已有预览、3D handle、数值参数、节点拆分/合并、坡度工具等先例，可参考交互而不是宣称已集成。[作者 README](https://github.com/lucarager/CS2-NetworkTools)
- Anarchy 可以绕过若干施工报错，但不等于车辆能正确走、净空足够或网络不会被删除；启用时项目诊断仍应保留，绝不自动绕过所有红灯。[作者 README](https://github.com/yenyang/Anarchy)
